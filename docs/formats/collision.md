# Level collision mesh (NGP node type 42 / 0x2A) — decoded from the engine
Parser: `tools/collision.py` · Runtime: `src/ground.hpp` (`Ground::query`) · Tests: `tests/test_collision.py`, `tests/ground_test.cpp` (synthetic) · Real-data check: `tests/ground_pts_check.cpp`.
Rule for this doc: every statement cites the ELF function (Ghidra address); anything uncited is marked **hypothesis**.

## How the bike finds ground (call chain)
1. `FUN_001340d8` (body step) — per sub-step sweeps the body's contact points (16-B vectors from `body+0x150`, count `body+0x12c`) from the previous to the new position, with a radius, into `FUN_0021a908`; then `FUN_00217450` picks **the hit with the smallest fraction `hit+0x1c`** (tie: lower address). Hits are 0x30 B. If the earliest hit has fraction < 0 → `FUN_001344f0`; otherwise `FUN_001344d0 → FUN_00134630` applies the contact response.
2. `FUN_0021a908` — builds the swept AABB (min/max of start/end ± radius), `FUN_00217e00` converts it to a cell range of the current grid (`DAT_002c7c48`: `+4,+6` i16 width/height, `+8` cell size, `+0xC/+0x10` x0/z0 — same header as NGP root node 15), `FUN_00218170/00217f48` iterate the cells' objects, and for each candidate calls `FUN_00216780` (or `FUN_00216a10` with extra params).
3. `FUN_00216780` dispatches on the candidate node type: **0x0A** → `FUN_0021a4d8` (single primitive; no node 10 occurs in the walked ALP2 tree: unknown shape), **0x2A** → loop over its parts calling `FUN_00219970` (swept sphere vs triangle part). After hits: `hit.u16[3] = surfaceTable[triMaterial]` (`puVar4[3] = *(u16*)(mat*2 + node[2])`).
4. `FUN_00134630` (response) reads the contact: point `+0x10`, normal `+0x20`, and **surface class = `(u64 word0 >> 0x35) & 0x3F`** = `(surface_u16 >> 5) & 0x3F`, passed to the effects function `FUN_001b9a50` (dust/sound). Impulse maths in `FUN_00238648` / `FUN_002384b8` (restitution `param_1+1.0`, tangential friction by `body+0x118`, ×1.25 when mode 2).

## Node 0x2A layout (`FUN_00216780`, branch 0x2A)
| off | type | meaning |
|----:|------|---------|
| 0 | u32 | `0x2A` (exact; the render walker `FUN_0020edb8` case 0x2A treats it as a callback hook, it never draws it) |
| 4 | u16 | number of parts `n` |
| 6 | u16 | unknown (4 in ALP2 example) |
| 8 | ptr | surface table: `u16[material]` |
| 0xC | ptr × n | parts |
Part layout (`FUN_00219970`): `+0 ptr` vertex array (f32 ×3, **u8 indices → ≤ 256 vertices**, array sits just before the part header), `+4 u16` triangle count, `+6 u16` BVH node count (0 → test all), `+8 f32×3` origin, `+0x14 f32` quantisation scale (`(p − origin)·scale` → i16), `+0x18` BVH nodes × 14 B (`i16[6]` min/max box + `u16`: bit0 = leaf, bits1-4 = triangle count, bits5-13 = first triangle or child index), then triangles × 4 B `(v0, v1, v2, material)`. **Verified on ALP2**: parts are contiguous (`part end` → next vertex array → next part …) and the surface table starts exactly where the last part ends.

## Instance transforms — CORRECTED 2026-10-02 (the "no evidence of any" paragraph that stood here was wrong)
**The 0x2A/0x0A node is in local space; the instance matrix lives in the *path* of its grid object record.** A grid object record (the same `0x4C`-style records that `FUN_00217e00/00218170` iterate, **hypothesis** for the exact consumer) is: `AABB (6×f32, world)`, `u32 0` (+0x18), `u16 flags` (+0x1C, 0xFFFF or 0), **`u8 n` (+0x1E)**, `u8 extra` (+0x1F), then `n` node pointers from +0x20 = the chain root → leaf. The leaf is the collision node (0x2A, 0x0A, or a type-11 hook for props); the transform is the product of the type-3 (translation) / type-4 (3×3 + translation) nodes of the chain, `m = local(node) · m_parent` (row-vector convention, same as `tools/scene.py: walk_payloads`). The earlier scan read `n` as a u16 and required `0xFFFF` at +0x1C, so it missed more than half of the records and concluded that no matrix exists.
Evidence (`tools/collision.py: find_instances`, 54 levels):
| check | result |
|---|---|

| transformed triangles inside the record's world AABB (±2 u) | **68 996 / 69 040 = 99.94 %**; without the matrix 1 of 1024 (MOAB), 1 of 241 (ALPINEMX), 1 of 16 (ALP2) non-identity records |
| matrices | pure rotation + translation: det = 1 ± 8e-8 and unit rows in all 1789 ALP2 chains (so triangle winding is preserved; no mirror) |

**Consequence:** the previous `.col` (one untransformed copy per node, `collision_tris`) put **7 % (ALP2), 33 % (ALPINEMX, CITY), 83 % (MOAB), 89 % (FUJI)** of its triangles in local space near the origin, and missed the extra instances (+9…16 k triangles). ALP2 and the grounded savestates were insensitive because the terrain nodes have identity chains. `instance_tris` / `collision.py --instances` is the correct export; `src/ngp.hpp: collisionTrisInstanced` now ports it (same record scan, chain matrix, dedupe by (leaf, matrix)); **bit-identical to `collision.py --instances` on all 54 levels** (`tests/ngp_col_check.cpp nivel.NGP nivel.col --instances`; ALP2 111 738 → 136 108 triangles). `tools/export_all.sh` now exports `.col` with `--instances`.

## Node 0x0A (convex planes) — present, 4 in all 54 levels
Layout (`FUN_00216780` branch 10, `FUN_0021A4D8`; `tools/collision.py: parse_node10`): `+0` header (low 6 bits = 10), `+4 u16` plane count `n` (6 in both MOAB cases), `+6 u16 0xFFFF`, `+8 u16` surface id **used directly** (`param_8[3] = (short)node[2]`, no table), `+0xC u32` 0, `+0x10` 4×f32 (cx, cy, cz, r) — **hypothesis**: bounding sphere as in 0x2A (r 7.10 and 5.63 in the two MOAB nodes; plane offsets w between 1.7 and 6.3), planes from `+0x20`, 16 B each `(nx, ny, nz, w)` with unit normals; inside ⇔ `n·p ≤ w` (`FUN_0021A4D8`: `fVar9 = w + r − n·p0`, a start point with `fVar9 < 0` on any plane is a miss). Sweep result: entry fraction `(fVar9 − 0.01)/(n·p1 − n·p0)` from the plane that is crossed last while entering, exit fraction from the first plane left; initial overlap when no entry plane (contact `p0 − n·(r − fVar12)…`, fraction −1 at +0xC). Only **MOAB and MOAB2** have any: 2 nodes each, 6-plane convex bodies (±x planes at w = 3.15, the y/z planes at different offsets and slightly tilted normals, e.g. (0, 0.99, −0.13); local origin), referenced by the chain `…, type-4 matrix, type-1 group` of two grid records (e.g. file 0xCA30C8 / 0xCA3110) → they are **placed by the same path matrices** (small wedge-like props; **hypothesis** on what they are). Not ported to C++ (`src/ground.hpp`): 4 boxes in 54 levels.
Validation (`tests/test_collision.py`): synthetic tests for node 0x0A and for the instance chain; `test_real_moab` (skipped without `unpacked/`) checks 1629 instances, 2 nodes 0x0A with their records and ≤1 instance outside the AABB.

## Sweep implemented in C++ (`src/ground.hpp`, `Ground::sweep`) — what is faithful and what is not
Port of the narrow phase and the selection rule; **no 30-u constant exists any more** (`groundQuery(x,y,z,r,reach)` takes radius and reach from the caller; dhview passes the mesh depth).

| Step | Engine | Port |
|------|--------|------|
| Selection | `FUN_00217450`: smallest `hit+0x1C`; tie → lower address | smallest `frac`, tie → lower triangle index |
| Swept box | `FUN_0021A908`: `[min(p0,p1)−r, max(p0,p1)+r]`, cells by `FUN_00217E00` | same box; own XZ grid of 100 u instead of the object grid (the engine's cells list *objects* registered at load; static result is identical because every triangle whose box touches the swept box is tested) |
| Triangle prefilter | `FUN_00219970` box test per axis | same |
| Face | `FUN_002193C0`: n=(v2−v1)×(v0−v1) normalised, one-sided (`dist0<0` → no hit); if `dist0−r ≤ 0` overlap at start (contact `p0+n·(0.01−dist)−r·n`, `frac=−FLT_MAX`, pen `0.01−dist`); else `dist1=n·p1−d−r > 0` → no hit (no edge test), `t=dist/(dist−dist1)`, `tb=t−0.01/(dist−dist1)`, inside test `c0·c1>0 ∧ c0·c2>0` | identical |
| Edges / vertices | `FUN_00218FB8` + `FUN_00218E00`: per-axis box reject, initial overlap with the edge segment, cylinder quadratic, then sphere at vertex `v_i`; min fraction of the three edges | identical formulas |
| Node type 0x0A (convex planes) | `FUN_0021A4D8` | **not ported**: only 4 nodes in the 54 levels (MOAB/MOAB2), parsed in `tools/collision.py: parse_node10` — see "Node 0x0A" below |
| `FUN_00216A10` variant (extra params `p[5],p[6]`) and object transforms (`FUN_00218268`/`FUN_00218310`/`FUN_002183F0`: world↔local with matrix at `obj+0x30…`) | | **static instances ported** in `src/ngp.hpp: collisionTrisInstanced` (matrices from the grid-record chains, see "Instance transforms — CORRECTED"); dynamic objects (kinds 5200–5299) do not exist in the level data |
| Multiple overlapping hits | the engine appends all hits with `frac ≤ 0` to the buffer and depenetrates over them (`FUN_001344F0`) | only the minimum is returned |
| Response `FUN_00134630` | impulse `FUN_00238648/FUN_002384B8`, surface class `(word0>>0x35)&0x3F` | `src/ride.hpp` removes the inward velocity component (inelastic); surface id is returned untouched |
Winding sign: `(v2−v1)×(v0−v1)`. It was first chosen empirically and is now **confirmed by the engine itself**: a savestate of ALPINEMX holds the engine's own hit records, whose normal equals this cross product to float precision and whose `w` equals `n·v1` (docs/p2s-savestates.md, table B).

## Demo (`ride_demo`, `dhview` ride mode)
Kinematic sphere (r = 0.75 u, g = 32.17 u/s², **1 u = 1 ft** — confirmed with a savestate, p2s-savestates.md), two sweeps per step like `FUN_001340D8`, autopilot toward the line 5 points ahead (**demo aids**, not engine behaviour: turn limit 2.5 rad/s on ground, 0.6 in air plus `airPull` 3 /s toward the target while airborne; the sphere cannot jump).
ALP2 result: start at line point 3 (the start-gate bar — surface 0x681D — is closed in the static mesh); the sphere falls into a bowl near line point 193 and 189, so after 8 s without progress the demo **repositions it 3 points ahead (2 resets, t = 67.7 s and 85.3 s)**; **28/28 course gates in order and the finish plane (8052) at t = 157.9 s**; 11 visual-mesh crossings of the centre, **all within 20 u above the collision surface (decorative floating sheets), 0 below**. Airborne 84 % of the time. An earlier run with the wrong scale (10 u = 1 m, r = 3) reached the finish in 62.7 s without resets; it was an artefact of the wrong units.
So it demonstrates *no tunnelling*, not realistic riding; without a jump/steering model the sphere cannot follow the line through the drops.

## Hito 3 prerequisites (2026-10-02): deep crossings and the 44 out-of-AABB records
**1. The "33 deep crossings" are decorative vegetation, not missing collision.** The earlier "0 below / all ≤ 20 u above" (docs above) was measured against a visual `.mdl` that did not yet contain the instanced props. With the *current* visual mesh the **old untransformed collision gives 51 deep crossings, the terrain-only instanced collision (identity-chain instances + orphans) also 51 and the full instanced collision 33** (`ride_demo`, same trajectory family: finish 28/28 at t = 157.9 s for old/terrain-only, 173.7 s with props solid). So instancing did not cause them; the solid props only reduce them (51 → 33) and change the path (3 resets instead of 2). Classification of the visual triangle crossed (scratch copy of `ride_demo` printing the visual texture id per deep crossing, vertex-0 texture of the triangle): ALP2 instanced collision, 33 crossings → texture ids 97 (×10) and 99 (×18) = dark foliage blobs, 101 (×4) = bare twigs, 103 (×1) = hanging roots; old collision, 51 → 96 (×2, a rock face, now covered by instanced rock collision), 97 (×12), 99 (×27), 101 (×7), 102 (×2, mossy log), 103 (×1). The first one (t = 13.7 s, mdl (−1496, −472, 4261)) has collision 11 u and visual foliage 3 u away. Verdict: **(c) decorative vegetation without collision** — the 100 % of the crossings are bush/branch/root sprites, not terrain or structures. **Hypothesis** that the engine also lets the bike pass through them (no collision node exists for those visual models; not checked in the engine's own state).
**2. The 44 records outside their AABB were a missing node type: type 30 (0x1E) in the chain.** 42 of the 44 had a type-30 node in their chain (all 111 records with such a node in the 54 levels: 42 failing, 69 fine). Its layout (data only, **hypothesis**, FUN not identified): `+0x10 f32×3` translation, `+0x20 f32×3` scale (`[tx ty tz 0 sx sy sz 0]`; e.g. BC `0xbc14ac`: t = (216, −11112.8, −12024.5), s = 1.1; the needed shift (216, −11112.6, −12016.3) matches). Semantics tested on all 111 records: `v' = v·s + t` (scale then translate, as one more chain matrix in chain order): fixes 40/42 failing, keeps 65/69 of the formerly-fine as single-node application and **all of them once composed in chain order** (`collision.py: local_inst`); the alternatives (scale about the node centre, translation only, `(v−c)·s + t`) fix fewer (9, 24, 0). Result: records outside AABB ±2 u **44 → 2**, hence MOAB's lone outlier, the 15+15 of AUBERMX/AUBERMX2 and the ones of ALP2, BC, CITYMX, CITYTDH are gone. Applied matrices in a 54-level scan: no `.col` change in ALP2 total (136 176) or in the ground-validation numbers of FUJI/MOAB (the type-30 nodes belong to props). `src/ngp.hpp: localMatrix` mirrors it; C++ is bit-identical to Python on 54/54 levels.
