# Rider body meshes / mallas del cuerpo de los pilotos
Tool: `tools/export_riders.py` (+ `tools/extract_model.py`, vertex branch "piloto"). Evidence: ALP2 + savestate slot 05 (10 riders). Uncited = hypothesis.

## Where they are (found 2026-10-02)
**Not in `R/` (first-person hands, extents ±2 u, no body) and not in `BIKE/`.** The rider bodies are **inside each level's `.NGP`** (every level carries its own copy), as scene nodes the static walker never visits:
* `type 1` group, `kind` 4030-4050 / 4090-4110 / 4120-4130 → child **`type 25`** node (same kind) → `+0x2c` pointer to a **`type 1` group (kind 0) with three children**: a **`type 35`** node (0x23; bone table, see below), a **`type 2`** selector whose entry points at the VIF chain (`type 0` payload), and a `type 42` node (bounds).
* Instancing: one `type 1/25` pair **per rider slot** sharing the same payload (ALP2: 10 nodes for each of 4090…4110, 4 for each of 4030…4050, 1 for 4120…4130) → **13 distinct models in ALP2**: 4090-4110 = the five racers with helmets (green/orange/blue/grey/teal outfits), 4030-4050 = hikers with backpacks, 4120-4130 = bystanders (one with a camera tripod). `scene.py` comment "kinds 4000-4499 = rider parts (FUN_00195b80)" was right; `DH_KINDS` alone cannot reach them because `Scene.children` does not descend type 25 (follow `+0x2c`).
* RAM confirms: the rider object (`0x2D94C0 + i·0x7BD0`, docs/p2s-savestates.md) holds ~16 `(0x15f7b10, anim instance)` pairs at `+0x30/+0x34, +0x60/+0x64, …`; the shared target is a type-25 node (`0x0e100019` = kind 900) whose `+0x2c` payload is the same `0x11, 3, 0, 1.0f, ffff,0,1,2,3,4,5` table as `type 35`; the anim instances are type 0x21 clip players pointing into `BANIM.NGA` (resident at `0x9d1a90`).

## Vertex format (differs from level meshes)
Chain = `UNPACK S-32 (imm 0xb4)`, **`UNPACK V4-32 ×N`** = `(x, y, z, w)` per vertex (N ≈ 155-182, `imm 0xb5`), **`UNPACK V3-8 ×N`** (signed-byte normals, ×127), `MSCALF 4`, then batches exactly as in level meshes: `V4-32 ×1` GIF tag (`0x8000|n` …), `S-8` strip indices, `V4-5` colour, `V2-16` UV, `MSCNT`. A payload is several such packets back to back (VU1 memory limit): ALP2 4090 = 167 + 182 + 155 vertices sharing vertices between packets. Coordinates are a **T-pose in feet** (arm span ±2.95 u, height 6.07 u; **Z up**, the same up axis as the world), left/right symmetric, first ~21 vertices on the x = 0 plane. `w` ∈ [0.45, 1.0] is a **packed skin weight** and the low bits of x, y, z are **bone ids** (see Skinning below; the "floats" are only exact to ~1e-5 because of that).
`extract_model.py` change: `rider` branch accepts `UNPACK V4-32 (n ≥ 16)` followed by `V3-8` of the same count as a position block, skips the whole chain afterwards (its `S-8`/`V2-16` bytes produce false `0x68/0x78` hits) and the inner loop stops at the next V4-32 block of ≥ 16 vectors (it used to run into the next packet). `DH_RANGE=lo,hi` restricts the scan to one chain (debug).

## Skinning (VU1 microcode, read from the disassembly; `tools/vudis.py` on `.vutext`)
The program at `.vutext` instructions `0x0c8d..0x0cc4` (entry for chains of this kind; reads the vertex count at VU address `0xb4`, vertices at `0xb5`, normals at `0x175`) does, per vertex `(x, y, z, w)`:
* `MTIR vi1/vi6/vi3 ← x/y/z` and `IAND 127`: **the low 7 bits of the three float words are three bone ids** (always multiples of 4: id = 4 × palette index, 15 bones → 0..56). `LQ vf21..24, 856+id(vi)` = the 4×4 bone matrix at VU address `0x358 + id` (matrix palette uploaded by the engine, 4 qwords per bone).
* `w·2048` → `FTOI0/ITOF0` → fractional part: **weights = (w, frac(w·2048), 1 − w − frac)** on the three matrices (`MULAw/MADDAw/MADDw`): the integer part of `w·2048` is the first weight quantised to 1/2048, the 13 low mantissa bits carry the second weight. In every one of the 167+182+155 vertices checked the third weight is 0 (−8e-5) → effectively **two bones per vertex**. Verified: the weighted bone sets are spatially coherent (spine verts use palette 0/1/2, hands 4/5 and 7/8, hip region 12/13) and the skinned result is smooth.
`extract_model.py` writes this as a sidecar when `DH_SKIN=path` is set (`DHSK`, `u32 n`, per output vertex `3×u8 bone, pad, 3×f32 weight`, same order as the `.mdl`).

## Skeleton (decoded 2026-10-02, `tools/rider_skel.py`)
The `type 35` nodes are the joints; they form a tree through their tables. **Joint node** (0x50 B): `u32 0x23, u32 1, u16 n (bone number), u16 0, u32 ptr → table, 4×4 inverse bind matrix` (row-vector convention; translation row = −world position of the joint in the T-pose). **Joint table** (0xE0 B, `type 17`): `u32 0x11, u32 nchildren, u32 0, f32 1.0 | u16[8]: [ffff, chX, chY, chZ, (root: 3 more), …] (pose-channel indices, ffff = none) | qword (0,0,0,1) | +0x30 vec3 loc (bind offset in the parent frame) | +0x40 4×4 and +0x80 4×4 (identity; +0x80 = bind rotation, diag(−1,−1,1) for the left shoulder) | +0xC0 u32 flags (0x300 normal, 0x20300 left-arm root = apply the +0x80 rotation, 0x1F00 root) | +0xC4 u32 palette index | +0xCC child node pointers` (`+0xD0` onwards is the next node).
The **palette index = pre-order of the tree** (children in table order) = bone id / 4 used by the vertices. ALP2 4090 (all 13 models share this skeleton layout): 0 pelvis (root, z = 3.548), 1 spine (+0.75), 2 head (+0.9), 3 shoulder R → 4 elbow R (hinge, channel 15) → 5 wrist R, 6 shoulder L (mirrored frame) → 7 elbow L (22) → 8 wrist L, 9 hip R → 10 knee R (hinge, 29) → 11 ankle R, 12 hip L → 13 knee L (36) → 14 ankle L. Segment length 0.912 (arm), 1.38 (leg). **Euler channels**: pelvis 0-2 (+ 3-5 = second triple, root translation, hypothesis), spine 6-8, head 9-11, shoulder R 12-14, elbow R 15, wrist R 16-18, shoulder L 19-21, elbow L 22, wrist L 23-25, hip R 26-28, knee R 29, ankle R 30-32, hip L 33-35, knee L 36, ankle L 37-39 → **40 channels**.
Engine (`FUN_0020effc` case `0x11` @`0x20f4e8`): reads `pose[ch]` for slots 1-3 into `table+0x20..0x28`, **negates** them, builds the rotation with `FUN_00227da8` (rows in memory = `Rx(a)·Ry(b)·Rz(c)`, with `a,b,c` = the negated x,y,z values — order x,y,z is a hypothesis, `vcallms 0x978` not read), multiplies by `table+0x80` when `flags & 0x20000` (and by `+0x40` when `flags & 0x10000`; no joint has that bit), adds `loc` to row 3 (`FUN_00227698` = `A·B`, rows of A times B). World = local × parent world; skin = inverse bind × world. At zero angles the product is the identity to 2e-7 on ALP2 4090 (`tools/rider_pose.py`, `tests/test_rider.py`).

## Animation source
`BIKE/BANIM.NGA` has 193 of its 198 clips with exactly **27 tracks on channels 0-26** = pelvis, spine, head and both arms (the first 27 of the 40 channels): upper-body poses/animations for the rider (e.g. clip 4/9/50 at t = 0: spine channel 6 = 0.44 rad, shoulders `(0.95, 1.57, ±0.49)`, mirrored left/right as expected). Channels 26-39 (legs) are not in those clips (**hypothesis**: legs are driven separately, e.g. by IK to the pedals). The other `.NGA` files are different rigs (`R/RANIM`: first-person hands, channels up to 116). The rider object in RAM holds ~16 type-0x21 clip players pointing into BANIM (`docs/p2s-savestates.md`).
`tools/rider_pose.py model.mdl model.skin level.NGP 0x9e2f40 BANIM.NGA <clip> <t> out.mdl` poses a rider: with clips 4, 9 and 50 the arms come forward-down (hands at chest height, forearms bent) and the mesh stays smooth. Not yet verified against the game (the savestate screenshots show the pose from behind only).
