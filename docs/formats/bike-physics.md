## Model (src/bike.hpp)
State: position (centre of mass), velocity, angular velocity, and **only the forward vector** `fwd` as orientation: `right = fwd × Y`, `up = right × fwd` (roll locked). Semi-implicit Euler: forces change velocity first, then the sweep moves the body with the new velocity and the contact impulses (`contactResponse`) edit velocity/angular velocity at the hit points.
Per sub-step (≤ 1/120 s): controls and forces → up to two sweeps (all 4 points, rotation included) → depenetration for initial overlaps → response at the earliest hit → remaining time advances unchecked (a residual overlap is fixed by the next step).

## What is a hypothesis (tuning knobs in `BikeParams`)
| knob | value | why |
|---|---|---|
| roll lock | orientation = (heading, pitch) | all contact points have x = 0, so a rigid body alone would fall sideways; the engine keeps the bike upright with some other controller that is not studied |
| `comLift` | 1.4 u | all local points shifted up (centre of mass lower, closer to the wheel axle). The engine gives points relative to the node and the COM is offset (`+0x50`) by an unknown amount; with COM at the node the bike nose-flips on every steep landing |
| `pedalAccel` 6 u/s², `pedalMax` 40 u/s | pedalling force falling to 0 at 40 u/s | HUD of the game shows ~60 km/h (55 u/s) on slopes; previous cinematic mode used 4.9 u/s² |
| `brakeDecel` 28 u/s² | never reverses | |
| `rolling` 0.03 /s + `rollConst` 0.8 u/s² | rolling resistance; the constant part stops the bike on flat ground (the proportional part left 0.3 u/s creep) | |
| `drag` 0.003 /u | quadratic; terminal ~70–85 u/s on 25°–40° slopes (savestates: 85 u/s in the long ALP2 drop) | first value (0.0012) reached 147 u/s = 161 km/h |
| `grip` 10 /s | tyres remove lateral velocity; the engine only has the anisotropic friction in `FUN_00134630` (it removes the forward component of the friction impulse: `N × axis0`, `|.|² > 0.5`), whose magnitude is too small to steer | |
| steering | yaw rate `1.5 / (1 + 0.03·speed)` rad/s on the ground, kept in the air | previous mode: 1.6/(1+0.04·v/U) |
| lean (Q/E) | 7 rad/s² about the lateral axis, pitch rate clamp ±8 rad/s | player control in the air / wheelies; not studied in the engine |
| hop (Space) | +9 u/s along `up` when the bike touched the ground in the last 0.1 s | |
| `angDamp` 0.975 per 1/50 s | on pitch rate | see table above |
| start gate | triangles with surface 0x681D removed (`openStartGate`) | the bar is closed in the static mesh (`collision.md`); the game opens it at the start |
| respawn | last point where both wheels touched for ≥ 0.5 s, every 0.5 s | the real game's respawn is not studied |
| visual lean | cosmetic roll ≤ 0.45 rad when steering (not in the physics) | |

## EN — Riding controller read (2026-10-06; hypotheses unless a number is given)
Read from the pseudocode of `FUN_00136A88` (pedalling), `FUN_00136330` (forces) and `FUN_00135D28` (tick); two auxiliary models read `FUN_00135D28`/`FUN_00136330` independently and agree on the structure only (provenance outside the repo).
- **Pedal force** (`FUN_00136A88`): `F = m·50·0.5 = 2500` (X = 50.0) × state factor × surface factor (class `0x16` → ×1.15, `0xB` → ×1.25) × `rider+0x791C`, along `normalize(n_wheel × node.row0)` (fallback `node.row1`), added to the force accumulator. It returns early when `rider+0x4098` bit 2 is set, or with no input (`rider+0x7A78 == 0` and byte `rider+0x7A69 == 0`) unless the state pointer `rider+0x4ECC == rider+0x5E70`. Input: `+0x7A78` is an analog float (scales by `· 0x77A7E8`), byte `+0x7A69` is a button (×1.5 · `rider+0x3F58`). A speed regulator follows: if `|v|² < limit²` with `limit = gp(-0x7DD8)·1.4666667` (mph → ft/s) and the wheel state allows, `ctrl+0xC0` gets `dir·limit·gp(-0x7DD4)` and `FUN_00238B38` is called (the two `gp` values are not in the captured RAM: unknown). `src/bike.hpp` keeps its own pedalling (60 u/s², fade at 50 u/s) as a **hypothesis**; the only engine element added is the sprint button (×1.5, `BikeInput.sprint`, key Shift).
- **Drag coefficient is derived, not constant** (`FUN_00136330`): `k = g_eff / v_t²`, `g_eff = ctrl+0x418 · G0 · 32.2`, `v_t = 90 · (ctrl+0x428 + (m − 100)·0.001) · 1.4666667 · ctrl+0x154 · rider+0x7AF0 · rider+0x7914` (×1.15 in the default state, sprint terms with `+0x7A69`), clamped to 1. With captured values (`0x418 = 2.45`, `0x428 = 1`, `0x154 = 1`, `0x7AF0 = 1`, `0x7914 = 0.85`) `v_t = 112.2` and **`k = 78.9/12589 = 0.00627` = the measured ground value**. In the air `0x418 = 2.47` with `G0 = 1.25` gives `99.4/12589 = 0.0079` = measured; the other air value (0.00744) would need `G0 ≈ 1.19` (open).
- **DISCREPANCY (not applied; needs the user's OK):** the same code gives the ground weight `m·32.2·0x418·G0 = 78.9..79.5 u/s²` (G0 = 1.0) and the air weight `98.6..99.4` (G0 = 1.25), whereas `bike.hpp` uses 96.6 everywhere (`FUN_00134060`, the rigid-body module). 78.9/96.6 = 0.82 would explain part of the fitted ground share (0.46 → 0.56 of the remaining force); the jump-arc check (range median 1.4 %) used 96.6 in the air and agrees within 2.3 % vertical.
- **Jump** (`FUN_00136330`, hypothesis): while the hop input is active and `ctrl+0x4A4 < 12.5` an impulse `m·0x418·J·rider+0x7920` is applied (`FUN_00237DB0`) with `J = 0x424 + f·(1 − 0x4A4·0.08)·(0x420 − 0x424)`, `0x424 = 13.0`, `0x420 = 19.25`, `f` = `FUN_0012E168(rider)` (a 0..1 charge input). `bike.hpp` keeps a single hop of 15.6 u/s (hypothesis).
- Not decoded: steering and lean (no engine input located), the wheel contact normals' use beyond the pedal direction.
**Controls added** (`src/controls.hpp`): W/↑ pedal, S/↓ brake, A/D or ←/→ steer, Q/E lean, Space hop (edge), Shift sprint; per-tick input log (`DH_INPUT_LOG=file`, saved when the race ends) and replay (`DH_INPUT_REPLAY=file`) at a fixed step of 1/60 s: two replays give identical frames. ## EN — The engine's steering controller (read 2026-10-06; hypotheses where marked)
