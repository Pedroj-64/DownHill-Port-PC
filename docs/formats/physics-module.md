- Per-tick step: `FUN_00133FA8` (caller `FUN_001586B8`, 0x1586F4; no direct caller of that one: vtable/indirect, **hypothesis**) → `FUN_00134060` (zero F/T, damp, gravity: see `integrator.md`) → `FUN_001340D8` (sub-step loop) → `FUN_00237A70(owner+0x40C0, body)`.
- Inside `FUN_001340D8`: contact points `FUN_001348A0` (0x134158, 0x1342AC, 0x1342F4), sweep `FUN_0021A908` (0x13430C), first hit `FUN_00217450` (0x13431C, 0x134454), depenetration `FUN_001344F0` (0x13436C), response `FUN_001344D0` (0x13441C). Other users of the sweep (not the bike): `FUN_00131C90`, `FUN_00131928`, `FUN_00146D70`, `FUN_00158B50`, `FUN_00167190`, `FUN_001A98D8`, `FUN_001AEF68`.
- Body functions (0x237xxx-0x238xxx): `FUN_00237960` (P, vel `*= k`), `FUN_00237998` (L, ω `*= k`), `FUN_00237C78` (F=T=0), `FUN_00237C88` (F += v), `FUN_00237CF0` (impulse), `FUN_00238818` (integrator).
- Shape/contact structures: shapes are the 4 sphere points above (no mesh); the collision "shape" side (BVH parts, `FUN_00219970`) is in `collision.md`. Contact response: see *Impact response* below.

## EN — Impact response (mapped 2026-10-04 from the disassembly), data first
**Hit record** (0x30 B, produced by the sweep; `a1` of `FUN_00134630`): `+0x00` u64 with packed fields (material index = `(u64 >> 21) & 0xFFFF & 0x3F`, used to pick the dust/sound effect; other bits **hypothesis**), `+0x10` vec4 contact point (world), `+0x20` vec4 surface normal (world), unit length (0x134828-0x13483C).
**Module fields used:** `+0x114` restitution e (0.2), `+0x118` friction µ (0.28; ×1.25 when the point index is 2, 0x134660-0x134674), `+0x1D0` counter reset to 0 after an effect fires, global u32 at `gp − 0x7E28` = 0x2C5348 (cool-down threshold for `+0x1D0`; value not read), owner `+0x7720` (sound sink), `+0x792C` (effects block; byte `+5` = enabled), `+0x7A44`.
**Functions.**
- `FUN_001344D0(module, hit, pointIndex)`: tail call of `FUN_00134630`; the result is the "responded" flag of the sub-step loop (always 1, 0x134878).
- `FUN_00134630(module, hit, pointIndex)` (body = `module + 0x10`, node = `*(module + 8)`):
  1. `J_f = FUN_00238648(body, out, v_surf = 0, hit.point, hit.normal)`; `J_f.xyz *= µ`.
  2. `t = hit.normal × node.row0` (row 0 = lateral axis, node `+0x40`; 0x1346B8-0x1346D0), normalised with `rsqrt`; **if `|t|² > 0.5`** (before normalising): `J_f −= t·(J_f·t)` (anisotropic friction: the component along `t`, the rolling direction, is removed).
  3. `FUN_00237D28(body, J_f, hit.point)`.
  4. `J_n = FUN_002384B8(body, …, hit.point, hit.normal, e)`, then `FUN_00237D28(body, J_n, hit.point)` (the normal impulse uses the velocity already changed by the friction impulse).
  5. `|J_n| > 400.0` and `+0x1D0 ≥ gp[−0x7E28]`: `FUN_001D03B0(owner+0x7720, |J_n|)`, `+0x1D0 = 0`, then if the effects byte is set `FUN_001B9A50(…, material, |J_n| × 5.0e-4 (0x3A03126F), …)`. Cosmetic: **not part of the dynamics**.
- `FUN_00238648(body, out, v_surf, point, normal)`: `r = point − pos(+0x50)`; `v = vel(+0xC0) + ω(+0xD0) × r − v_surf`; `vn = n·v`; if `vn > −0.001` (0xBA83126F) → `out = (0,0,0,1)` (separating); else `t = v − n·vn`, `|t|`, `t̂ = t/|t|` (**no guard** for `|t| = 0`), `K = invMass + t̂·((I⁻¹(r × t̂)) × r)` (`I⁻¹` = body `+0x80` via `FUN_002275F0`), `out.w = |t|/K`, `out.xyz = −t̂·|t|/K`: the impulse that cancels the tangential velocity (**sticking**, not clamped by the normal impulse: the Coulomb limit is replaced by the factor µ in step 1).
- `FUN_002384B8(body, out, v_surf, point, normal, e)`: same `r`, `v`, `vn`; separating test identical; `K = invMass + n·((I⁻¹(r × n)) × r)`; `j = −(e + 1)·vn / K`; `out.w = j`, `out.xyz = n·j`.
- `FUN_00237D28(body, J, point)`: `FUN_00237CF0(body, J)` (P += J, vel), then `L += (point − pos) × J` and `ω = I⁻¹·L` (`FUN_002275F0`).
- Native port: `src/contact.hpp` `contactResponse` (friction, anisotropy, normal impulse; effects not ported). Validation: see *Impact validation* below.

## ES — Respuesta a impactos (mapeada el 2026-10-04 desde el desensamblado), datos primero
**Registro de impacto** (0x30 B, lo produce el barrido; `a1` de `FUN_00134630`): `+0x00` u64 con campos empaquetados (índice de material = `(u64 >> 21) & 0xFFFF & 0x3F`, usado para elegir el efecto de polvo/sonido; el resto de bits **hipótesis**), `+0x10` vec4 punto de contacto (mundo), `+0x20` vec4 normal de la superficie (mundo), de longitud 1 (0x134828-0x13483C).
**Campos del módulo usados:** `+0x114` restitución e (0,2), `+0x118` fricción µ (0,28; ×1,25 si el índice del punto es 2, 0x134660-0x134674), `+0x1D0` contador que se pone a 0 al lanzar un efecto, u32 global en `gp − 0x7E28` = 0x2C5348 (umbral de enfriamiento de `+0x1D0`; valor no leído), propietario `+0x7720` (destino del sonido), `+0x792C` (bloque de efectos; byte `+5` = activo), `+0x7A44`.
**Funciones.**
- `FUN_001344D0(módulo, impacto, índicePunto)`: llamada final a `FUN_00134630`; su resultado es la bandera «respondió» del bucle de sub-pasos (siempre 1, 0x134878).
- `FUN_00134630(módulo, impacto, índicePunto)` (cuerpo = `módulo + 0x10`, nodo = `*(módulo + 8)`):
  1. `J_f = FUN_00238648(cuerpo, out, v_sup = 0, impacto.punto, impacto.normal)`; `J_f.xyz *= µ`.
  2. `t = impacto.normal × nodo.fila0` (fila 0 = eje lateral, nodo `+0x40`; 0x1346B8-0x1346D0), normalizado con `rsqrt`; **si `|t|² > 0,5`** (antes de normalizar): `J_f −= t·(J_f·t)` (fricción anisótropa: se quita la componente a lo largo de `t`, la dirección de rodadura).
  3. `FUN_00237D28(cuerpo, J_f, impacto.punto)`.
  4. `J_n = FUN_002384B8(cuerpo, …, impacto.punto, impacto.normal, e)`, luego `FUN_00237D28(cuerpo, J_n, impacto.punto)` (el impulso normal usa la velocidad ya modificada por el de fricción).
  5. `|J_n| > 400,0` y `+0x1D0 ≥ gp[−0x7E28]`: `FUN_001D03B0(propietario+0x7720, |J_n|)`, `+0x1D0 = 0` y, si el byte de efectos está activo, `FUN_001B9A50(…, material, |J_n| × 5,0e-4 (0x3A03126F), …)`. Cosmético: **no es dinámica**.
- `FUN_00238648(cuerpo, out, v_sup, punto, normal)`: `r = punto − pos(+0x50)`; `v = vel(+0xC0) + ω(+0xD0) × r − v_sup`; `vn = n·v`; si `vn > −0,001` (0xBA83126F) → `out = (0,0,0,1)` (se separa); si no, `t = v − n·vn`, `|t|`, `t̂ = t/|t|` (**sin guarda** para `|t| = 0`), `K = invMasa + t̂·((I⁻¹(r × t̂)) × r)` (`I⁻¹` = cuerpo `+0x80` vía `FUN_002275F0`), `out.w = |t|/K`, `out.xyz = −t̂·|t|/K`: el impulso que anula la velocidad tangencial (**adherencia**, sin limitar por el impulso normal: el límite de Coulomb se sustituye por el factor µ del paso 1).
- `FUN_002384B8(cuerpo, out, v_sup, punto, normal, e)`: mismos `r`, `v`, `vn` y prueba de separación; `K = invMasa + n·((I⁻¹(r × n)) × r)`; `j = −(e + 1)·vn / K`; `out.w = j`, `out.xyz = n·j`.
- `FUN_00237D28(cuerpo, J, punto)`: `FUN_00237CF0(cuerpo, J)` (P += J, vel), luego `L += (punto − pos) × J` y `ω = I⁻¹·L` (`FUN_002275F0`).
- Port nativo: `src/contact.hpp` `contactResponse` (fricción, anisotropía, impulso normal; efectos no portados). Validación: ver *Validación de impactos* abajo.

## EN — Impact validation and who drives the bike (2026-10-04)
**Bug found and fixed.** The port returned the friction impulse as `−t̂/K`; the disassembly gives `−t̂·|t|/K` (`|t|` stored at `sp+0x3C`, 0x238750; divided at 0x2387D4; written at 0x2387F4). The old form removed only `µ` u/s of tangential speed per call instead of `µ·|t|`. `tests/contact_test.cpp` expectations were updated accordingly.
**Oracle.** `tests/impact_replay_check.cpp` (manual: needs `nivel.col` and a numbers-only dump from `tools/impact_dump_ref.py`, both outside the repo) replays a full physics tick (`engine::preStep` + `integ::tick` with `Ground::sweepHits`, `FUN_001348A0` points, depenetration, `contactResponse`) from each recorded tick and compares with the next one. Capture `air_capture.py --lift 25` on ALPINEMX (slot 1), rider 1, 59 ticks:
| ticks | what | |Δpos| | |ΔR| | rel P | rel L |
|---|---|---|---|---|---|
| 0–26, 31–34, 36–40 | free flight | ≤ 9.8e-4 (≤ 1 ulp) | ≤ 1.8e-7 | ≤ 1.3e-7 | ≤ 1.2e-7 |
| 29, 30, 35 | impact responses | 9.8e-4, 2.4e-4, 4.9e-4 | 2.1e-4, 2.8e-4, 5.0e-4 | 8.6e-5, 7.1e-5, 2.0e-4 | 9.3e-4, 4.4e-4, 6.1e-4 |
| 27, 28 | first contacts | 0.18, 0.45 | 0.06, 0.18 | 0.48, 0.21 | 1.9, 0.13 |
With the old friction ticks 29/30/35 had L errors of 30 %/34 %/22 %. The impact ticks are at the 1e-4…1e-3 level, **not** at the float32 floor; proposed thresholds for impact ticks (to be approved): |Δpos| ≤ 3 ulp, |ΔR| ≤ 1e-3, rel P ≤ 5e-4, rel L ≤ 2e-3 (≈ 2× the worst observed). Only one capture and 3 clean impact ticks: **`contactResponse` stays wip**, not validated.
**Open (ticks 27–28).** The port produces at tick 27 exactly the state the game shows one tick later (P = (−1556, 3249, −3548) vs real (−1556, 3249, −3550)). The game applied at tick 27 a small impulse (|J| = 1226, direction (0.382, −0.666, 0.641), not a normal of our mesh) and the big hit one tick later; our sweep sees the big hit at tick 27 (point 3, frac 0.753) and misses the earlier contact. **Hypothesis:** the game has collision geometry our `Ground` lacks (the native collision covers 1 of 8 module types of `FUN_00216780`) or its sweep rejects that face at frac 0.75. Not resolved.
**The rigid body is not the riding model.** `FUN_001586B8` (virtual method, table slot 0x2905B4): if bit 3 of `*(u64)(rider + 0x4098)` is set it calls `FUN_00130138(rider, rider + 0x4ED0)` (state switch: virtual exit of the object at `rider + 0x4ECC`, virtual enter of the new one), else `FUN_00133FA8(rider + 0x6420)` (this module). A 12-s PINE capture of normal riding on ALP2 (slot 5, 601 samples): the module is inactive (`+8 = 0`, rigid velocity 0) and the node moves at 38–173 u/s (mean 75) on slopes of 36–44° with `dv/dt` 3–24 u/s² against `g·sinθ` = 56–67 u/s²: the real riding model has a speed limit near 80 u/s and is **not** the rigid body with `FUN_00134060` damping. The rigid body runs only in impact windows (~1.2 s). Candidates for the riding controller (**hypothesis**, not traced): `FUN_00135D28` (1532 B, calls `FUN_00131C90`, 3424 B, which calls `FUN_00217450` 8 times), `FUN_00136330` (1876 B, holds the only `32.2f`), `FUN_00136A88`, `FUN_00131928`, `FUN_00158B50`. Pedalling, steering and lean forces are there, not in the module.

## ES — Validación de impactos y quién conduce la bici (2026-10-04)
**Error hallado y corregido.** El port devolvía el impulso de fricción como `−t̂/K`; el desensamblado da `−t̂·|t|/K` (`|t|` guardado en `sp+0x3C`, 0x238750; dividido en 0x2387D4; escrito en 0x2387F4). La forma antigua quitaba solo `µ` u/s de velocidad tangencial por llamada en vez de `µ·|t|`. Se actualizaron las expectativas de `tests/contact_test.cpp`.
**Oráculo.** `tests/impact_replay_check.cpp` (manual: necesita `nivel.col` y un volcado numérico de `tools/impact_dump_ref.py`, ambos fuera del repo) repite un paso físico completo (`engine::preStep` + `integ::tick` con `Ground::sweepHits`, puntos de `FUN_001348A0`, despenetración y `contactResponse`) desde cada tick grabado y compara con el siguiente. Captura `air_capture.py --lift 25` en ALPINEMX (slot 1), piloto 1, 59 ticks: tabla de arriba. Con la fricción antigua los ticks 29/30/35 tenían errores de L del 30 %/34 %/22 %. Los ticks de impacto están en 1e-4…1e-3, **no** en el suelo float32; umbrales propuestos para impactos (pendientes de aprobar): |Δpos| ≤ 3 ulp, |ΔR| ≤ 1e-3, relP ≤ 5e-4, relL ≤ 2e-3 (≈ 2× el peor observado). Solo hay una captura y 3 ticks limpios: **`contactResponse` sigue en wip**, no validada.
**Abierto (ticks 27–28).** El port produce en el tick 27 exactamente el estado que el juego muestra un tick después (P = (−1556, 3249, −3548) frente a (−1556, 3249, −3550) real). El juego aplicó en el tick 27 un impulso pequeño (|J| = 1226, dirección (0,382; −0,666; 0,641), que no es normal de nuestra malla) y el golpe grande un tick más tarde; nuestro barrido ve el golpe grande en el tick 27 (punto 3, frac 0,753) y no ve el contacto anterior. **Hipótesis:** el juego tiene geometría de colisión que nuestro `Ground` no tiene (la colisión nativa cubre 1 de 8 tipos de módulo de `FUN_00216780`) o su barrido rechaza esa cara en frac 0,75. Sin resolver.
**El cuerpo rígido no es el modelo de conducción.** `FUN_001586B8` (método virtual, ranura 0x2905B4): si el bit 3 de `*(u64)(rider + 0x4098)` está activo llama a `FUN_00130138(rider, rider + 0x4ED0)` (cambio de estado: salida virtual del objeto en `rider + 0x4ECC`, entrada virtual del nuevo); si no, a `FUN_00133FA8(rider + 0x6420)` (este módulo). Captura PINE de 12 s rodando por ALP2 (slot 5, 601 muestras): el módulo está inactivo (`+8 = 0`, velocidad rígida 0) y el nodo avanza a 38–173 u/s (media 75) en pendientes de 36–44° con `dv/dt` de 3–24 u/s² frente a `g·sinθ` = 56–67 u/s²: el modelo real de conducción tiene un límite de velocidad cerca de 80 u/s y **no** es el cuerpo rígido con el amortiguamiento de `FUN_00134060`. El cuerpo rígido solo corre en ventanas de impacto (~1,2 s). Candidatas a controlador de conducción (**hipótesis**, sin trazar): `FUN_00135D28` (1532 B, llama a `FUN_00131C90`, 3424 B, que llama 8 veces a `FUN_00217450`), `FUN_00136330` (1876 B, contiene el único `32,2f`), `FUN_00136A88`, `FUN_00131928`, `FUN_00158B50`. Pedaleo, giro e inclinación están ahí, no en el módulo.
