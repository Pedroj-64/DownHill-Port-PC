# Audio: VAGp, VPK y tabla de pistas / Audio: VAGp, VPK and track table

**ES.** Hallazgos de 2026-10-16, validados con `python3 tools/audio_check.py --assert` (las 128 pistas de `VAG/` de la ISO decodificadas por `src/vag.hpp` **bit a bit iguales** a ffmpeg/libavcodec `adpcm_psx` en todo el tramo que ffmpeg entrega; ffmpeg corta el último trozo parcial de 40 pistas, el decodificador nativo lee la pista completa).

- **ADPCM (SPU de PS2):** bloques de 16 B = 28 muestras. Byte 0: `shift` (bits 0-3) y `filtro` (bits 4-7, 0-4; coeficientes {0,0},{60,0},{115,-52},{98,-55},{122,-60}); byte 1: bandera (`& 7`; ≥ 7 = fin/silencio); bytes 2-15: nibbles, el bajo primero, con signo. Muestra = `((n << 12) >> shift) + (h1·f0 + h2·f1) / 64` con división de C (trunca hacia 0); el historial (`h1`, `h2`) es la muestra SIN recortar; la salida se recorta a 16 bits. Esa aritmética es la de libavcodec: es lo que se puede verificar bit a bit; el hardware real recorta el historial (difiere solo en los pocos picos que saturan).
- **VAGp (mono):** `VAGp`, versión (BE; aquí 4), tamaño (BE +0x0C), frecuencia (BE +0x10, 44100), nombre en +0x20; ADPCM desde +0x30 (el primer bloque va a cero). ffmpeg interpreta la versión 4 como estéreo: para compararlo hay que parchear la versión a 3.
- **VPK (estéreo):** cabecera de 0x800 B little-endian: `" KPV"`, tamaño, offset de datos (0x800), **bloque (0xA000 = todos los canales)**, frecuencia, canales. Los datos alternan trozos de `bloque / canales` bytes (0x5000) por canal; el historial continúa entre trozos del mismo canal.
- **Pistas en la ISO (`VAG/`, 128):** `NN_LIC.VPK` ×20 (canciones licenciadas de la lista de reproducción del jugador: el ejecutable tiene un editor de listas y «5-song variety pack»), `<T>MX.VPK` y `<T>TDH.VPK` para 10 temas `T` (C, E, G, O, P, T1, T2, T, E2, HH; el ejecutable nombra «Hawaii TDH», «Peru TDH»), y por tema cuatro capas `DRUM/HIGH/LOW/MED` `-L/-R.VAG` (música dinámica por capas; mono L y R), más `SHELL1/2/3`. La tabla de nombres está en el ejecutable en `0x1A5B40-0x1A5E10` y `0x1BE4D8-0x1BE508` (cadenas); **no se ha leído el código que decide qué tema suena en cada nivel** (hipótesis abierta).
- **Reproducción en `dhview`:** `src/audio.hpp` (SDL3) toca una `NN_LIC.VPK` por nivel (hipótesis: una cualquiera de la lista del jugador); `DH_MUSIC=OFF|NN_LIC.VPK|CMX.VPK|...`, `DH_MUSIC_VOL`. Pendiente: efectos (`SND/*.BNK`, formato «SBlk»/«SUAP» sin descifrar), capas dinámicas, qué tema va con cada nivel.

**EN.** Findings of 2026-10-16, validated with `python3 tools/audio_check.py --assert` (all 128 `VAG/` tracks on the ISO decoded by `src/vag.hpp` **bit-identical** to ffmpeg/libavcodec `adpcm_psx` over the whole stretch ffmpeg delivers; ffmpeg drops the last partial chunk of 40 tracks, the native decoder reads the full track).

- **ADPCM (PS2 SPU):** 16-byte blocks = 28 samples. Byte 0: `shift` (bits 0-3) and `filter` (bits 4-7, 0-4; coefficients {0,0},{60,0},{115,-52},{98,-55},{122,-60}); byte 1: flag (`& 7`; ≥ 7 = end/silence); bytes 2-15: nibbles, low first, signed. Sample = `((n << 12) >> shift) + (h1·f0 + h2·f1) / 64` with C division (truncates toward 0); the history (`h1`, `h2`) is the UNCLIPPED sample; output is clipped to 16 bits. That arithmetic is libavcodec's: it is what can be verified bit by bit; real hardware clips the history (differs only on the few peaks that saturate).
- **VAGp (mono):** `VAGp`, version (BE; 4 here), size (BE +0x0C), sample rate (BE +0x10, 44100), name at +0x20; ADPCM from +0x30 (the first block is zero). ffmpeg reads version 4 as stereo: patch the version to 3 to compare.
- **VPK (stereo):** 0x800-byte little-endian header: `" KPV"`, size, data offset (0x800), **block (0xA000 = all channels)**, sample rate, channels. Data alternates chunks of `block / channels` bytes (0x5000) per channel; the history continues between chunks of the same channel.
- **Tracks on the ISO (`VAG/`, 128):** `NN_LIC.VPK` ×20 (licensed songs of the player's playlist: the executable has a playlist editor and "5-song variety pack"), `<T>MX.VPK` and `<T>TDH.VPK` for 10 themes `T` (C, E, G, O, P, T1, T2, T, E2, HH; the executable names "Hawaii TDH", "Peru TDH"), and per theme four layers `DRUM/HIGH/LOW/MED` `-L/-R.VAG` (layered dynamic music; mono L and R), plus `SHELL1/2/3`. The name table is in the executable at `0x1A5B40-0x1A5E10` and `0x1BE4D8-0x1BE508` (strings); **the code that decides which theme plays on each level has not been read** (open hypothesis).
- **Playback in `dhview`:** `src/audio.hpp` (SDL3) plays one `NN_LIC.VPK` per level (hypothesis: any track of the player's list); `DH_MUSIC=OFF|NN_LIC.VPK|CMX.VPK|...`, `DH_MUSIC_VOL`. Pending: effects (`SND/*.BNK`, "SBlk"/"SUAP" format not yet deciphered), dynamic layers, which theme goes with each level.
